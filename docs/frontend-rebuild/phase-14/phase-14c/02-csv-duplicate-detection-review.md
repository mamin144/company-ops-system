# Phase 14C — الوثيقة 02: مراجعة كشف تكرار استيراد CSV (CSV Duplicate Detection Review — O11)

> **الهدف:** حلّ عائق O11 التقني (توافق كشف التكرار بين الواجهة والخلفية) بقدر ما تسمح به الأدلة الآمنة — **دون تخمين مفتاح الخلفية**.
> **القيود:** لا فتح للملفات المحمية (`apps/api/src/**` بينها `import.routes.ts`)؛ لا تغيير لحد الـ200 صف؛ **لا تنفيذ استيراد**؛ لا عمل قاعدة بيانات.
> **التاريخ:** Tue Nov 17 2026

---

## 1. السلوك الحالي في الواجهة — `VERIFIED`

مصادر: شيفرة الأرشيف في Phase 13 (`Archive`/منطق الاستيراد) + اختبار `verify/archive.spec.ts` (L157–208) — مقروء مباشرة.

| الخاصية | السلوك المؤكد | الدليل |
|---|---|---|
| حد الصفوف | ≤ 200 صف لكل استيراد (لا تغيير — O11) | شيفرة الواجهة [Verified]؛ O11 |
| خطوات الحوار | رفع ملف → مطابقة أعمدة (تلقائية من الترويسات العربية) → مراجعة الصفوف → الملخص والتأكيد → تنفيذ/إلغاء | archive.spec.ts L159–204 |
| **مفتاح كشف التكرار** | **حقل `number` (رقم المستند)** — تكرار داخلي بين صفوف الملف/مع السجلات | رسالة «رقم مكرر — سيُتخطى» + منطق الفحص [Verified واجهة]؛ 14B-01 §4.8 (A5) |
| معالجة التكرار | الصف المكرر يُعرض في «مراجعة الصفوف» مع «رقم مكرر — سيُتخطى» + **خيار «تضمين» (checkbox)** يمكن المالك من إدراجه رغماً؛ العدادات تتغير ديناميكيًا (سيُضاف: 1→2، سيُتخطى: 3→2) | archive.spec.ts L166–179 [Verified] |
| رفض صيغة/حالة | «العنوان مطلوب» للعنوان الغائب؛ «حالة غير معروفة: nonsense» لحالة خارج المجموعة | archive.spec.ts L165–167 |
| إعادة التحقق عند تغيير المطابقة | تعديل تعيين الأعمدة يعيد تقييم كل الصفوف (التكرار يختفي/يظهر حسب التعيين) | archive.spec.ts L181–193 |
| الإلغاء بلا أثر | مسار إلغاء يترك عدّ السجلات كما هو | archive.spec.ts L195–197 |
| التأكيد الجزئي | تنفيذ يضيف فقط الصفوف المقبولة (+1 toast) ويعرض النتيجة | archive.spec.ts L199–207 |

**الحكم على A5 (افتراض 14B):** تحول من «قابل للنقض» إلى **مؤكد على مستوى الواجهة** — المفتاح المرئي للعميل هو `number`. لا دليل على أنه المفتاح الوحيد (قد يفحص الخلفية شيئًا إضافيًا).

## 2. أدلة الخلفية — `BLOCKED — OWNER AUTHORIZATION REQUIRED`

| السؤال الدقيق | لماذا المصدر المحمي ضروري | الملفات المطلوب مراجعتها بمصادقة |
|---|---|---|
| ما مفتاح كشف التكرار الخلفي للـ import؟ هل يفحص `number` فقط أم (number+type) أم معرف داخلي؟ | السؤال يجيب حصريًا من تنفيذ مسار الاستيراد | `apps/api/src/modules/.../import.routes.ts` (وما يخدمه: repository/service إن وجد) |
| هل يطبق الخلفية حد الـ200 صف أم حداً آخر؟ | التنفيذ الفعلي للحدين في الخادم | نفس الملفات |
| هل الاستيراد يعمل حاليًا عبر API (endpoint موجود) أم هو واجهة fixture فقط؟ | جرد endpoints موثق في 03 §13 [Unknown خلف المحميات] | نفس الملفات + `routes/index.ts` |
| هل يتطلب الرفع `archive.upload` + نطاق مشروع ≥ WRITE (ترجمة O13)؟ | التخويل داخل `projectScope.ts`/`authorization.service.ts` | الملفات الثلاثة |
| هل يوجد قيد تفرّد في DB على رقم المستند (يرفع التكرار كخطأ DB)؟ | مخطط DB الفعلي | migrations SQL تحت `apps/api/src/database/migrations/` (وجود ملفات مثبت بالاسم — المحتوى محجوب) |

**قاعدة صارمة:** عدم فتح المصدر لا يثبت وجود ميزة أو غيابها. لا يُكتب أي استنتاج عن سلوك الخلفية.

## 3. هل تتفق الواجهة والخلفية؟ — لا يمكن الحسم الآن

- الواجهة: تكرار بـ `number` → تخطٍ افتراضي مع إمكانية تضمين صريح.
- الخلفية: غير قابلة للفحص. الخيار الوحيد الصادق: **بقاء التطابق غير محسوم** حتى المراجعة المصرَّ بها. عقد API المقترح (14B-03 §5.5) يفترض مفتاح `number` — يبقى [Proposed] غير مثبت.

## 4. حالات الاختبار المطلوبة (بعد إزالة العائق)

1. تكرار داخلي بين صفين في نفس الملف بنفس `number` → تخطٍ افتراضي؛ إحصاء صحيح.
2. تكرار مع سجل موجود (number مطابق لسجل قائم) → نفس المعاملة + عدّ «سيُتخطى».
3. تكرار بحالة مختلفة لنفس الرقم → يُحدد السلوك المعتمد بعد المراجعة (تخطٍ أم خطأ متميز).
4. خيار «تضمين» الصف المكرر → يُضاف فعلاً؛ ماذا لو أصبح DB يرفض التفرّد؟ (تناغم العدادات مع استجابة الخادم).
5. ملف 199/200/201 صف → الحد يُفرض دون استبدال صامت (413/400 صريح).
6. صف برقم فارغ → القاعدة (إلزامية العنوان تُغطى؛ صلاحية number الفارغة غير موثقة — تُحسم مع المراجعة).
7. أحرف/تشفير CSV (BOM، UTF-8) وصياغة الترويسات العربية → المطابقة التلقائية.
8. فشل جزئي في المنتصف (صفان من 50 يرفضهما الخادم) → استجابة موحدة: ما يُنجَز وما يُرفض، بلا استبدال صامت.
9. التخويل: مستخدم بلا `archive.upload` أو بلا نطاق WRITE → 403 قبل أي تحليل.
10. التدقيق: استيراد ناجح/مرفوض يُسجل (S12/INT-3).

## 5. ما يبقى مجهولًا (سجل صادق)

- المفتاح الخلفي الفعلي + وضعه عند التكرار (خطأ/تخطٍ/upsert).
- وجود endpoint الاستيراد إطلاقًا في الخلفية.
- قيود تفرّد DB على رقم المستند.
- حد الخادم للصفوف.
- قناة الفيديو بين عدادات الواجهة ونتيجة الخادم عند «تضمين» صف مكرر (لو فرض DB تفرّدًا).

**إغلاق O11 لـ 14C:** الجزء القابل للفحص أُغلق بادلة (`VERIFIED` على مستوى الواجهة + حالة اختبار). الباقي موثق كعائق واحد محدد: **مراجعة مصدر مصرَّ بها لـ import.routes.ts وما يخدمه + قيود DB** — شرط قبل تثبيت عقد 03 §5.5 وقبل أي تنفيذ استيراد.
