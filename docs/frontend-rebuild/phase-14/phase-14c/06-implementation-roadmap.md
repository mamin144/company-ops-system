# Phase 14C — الوثيقة 06: خريطة الطريق التنفيذية (Implementation Roadmap)

> **الهدف:** تسلسل عملي لتوصيل وظائف قابلة للاستخدام — لا عملية تدقيق لا نهائية. لكل حزمة: النطاق، النتيجة، التبعيات، schema/API/واجهة/تخويل، استراتيجية اختبار، معيار قبول، مخاطر، قرارات حاجبة.
> **قواعد:** لا تقديرات زمنية ولا تواريخ؛ لا تنفيذ هنا؛ كل بوابات مراجعة المصدر تسبق التنفيذ الموازي.
> **التاريخ:** Tue Nov 17 2026

---

## 0. خريطة الأولوية

| المستوى | المعنى |
|---|---|
| **P0** | أساسيات حاجبة — بدونها لا يبدأ أي بناء موثوق (مراجعة مصدر مصرَّ بها، schema أساس، مفردة صلاحيات، Adapt مشاريع) |
| **P1** | الإصدار الأول القابل للاستخدام — الموديولات الستة بوظائفها الجوهرية |
| **P2** | تحسينات بعد الإصدار الأول (استيراد CSV، إعادة تعيين ذاتية، تعزيز الجلسة) |
| **Deferred** | مؤجل صراحةً (O5/O6 مالي، استرجاع تشغيلي، أدوار مخصصة، دخول بالإيميل) |

**البوابة الأمامية الموحدة (Gate-G):** مراجعة مصدر مصرَّ بها (الملفات الـ18 + migrations + مخطط DB للقراءة فقط) → تثبيت جرد endpoints والقيود → ثم تُفتح P0 التنفيذية.

## 1. P0 — الأساسيات الحاجبة

### WP-0.1 مراجعة المصدر المصرَّ بها (Owner-authorized review — بوابة، ليست تنفيذًا)
- **النطاق:** فتح للقراءة فقط: 18 ملف `apps/api/src/**` المحمية + ملفات `apps/api/src/database/migrations/*.sql` (+ فحص مخطط DB للقراءة إن لزم).
- **النتيجة:** جرد endpoints الموجودة فعليًا؛ مفتاح كشف تكرار الاستيراد الخلفي؛ قيود DB الفعلية (email، تفرّدات projectCode/username/ipcNumber، وجود أعمدة الحذف)؛ بنية filePath وقائمة أنواع الملفات؛ قيم SameSite/Secure للـ refresh.
- **التبعيات:** مصادقة مالك صريحة (لا شيء قبله).
- **معيار القبول:** تقرير جرد موثق يُثبّت أو يفنّد بنود 07-UNKNOWN/BLOCKED؛ عقد 03 §5.5 (استيراد) يُثبّت أو يُعدَّل.
- **المخاطر:** قد تنكشف فروقات بين النموذج المنطقي 14B-02 والفعلي → تُعالج additive-only.
- **قرارات حاجبة:** تصريح مالك بالمراجعة (يتاح خارج 14C).

### WP-0.2 أساس المخطط (Schema foundation)
- **النطاق:** بعد WP-0.1: تصميم وتنفيذ migration إضافية — `users.department/title` (nullable)، `projects.deleted_at/deleted_by`، `ipc_status_events`، قيمة `under-review`، (اختياري P1) `audit_logs.projectId`.
- **التبعيات:** WP-0.1 (القيود الفعلية)؛ لا يُنفذ على قاعدة حية إلا بمصادقة.
- **schema:** additive-only (03 §5)؛ **email خارج أي migration**.
- **اختبار:** migration على نسخة مطابقة/تطوير؛ قراءات قائمة لا تنكسر؛ rollback موثق.
- **معيار القبول:** migration واحدة قابلة للإعادة؛ لا rename/drop؛ INT-3 (تدقيق ضمن معاملة) جاهز.
- **مخاطر:** تعارض مخطط فعلي (R4) → تُعدَّل التصاميم لا القيود الموجودة.

### WP-0.3 مفردة الصلاحيات (B1)
- **النطاق:** إضافة `ipcs.approve`+`ipcs.resubmit` إلى `ALL_PERMISSIONS` (مع إعلان أثر admin الاحتوائي) + فرض SELF_APPROVAL_DENIED في محلل الانتقالات (قد يكون موجودًا — يُتحقق في WP-0.1).
- **التبعيات:** D1 (إسناد الأدوار — قرار مالك؛ يمكن الإطلاق بلا إسنادات: لا أحد يملكهما إلا بتجاوز GRANT صريح).
- **اختبار:** مصفوفة تخويل (admin/management/technical/warehouse/viewer × approve/resubmit/resubmit-via-edit × self)؛ DENY يقطع.
- **معيار القبول:** فعّال = لا اعتماد ذاتي بأي مسار؛ لا دور جديد مُخترع.

### WP-0.4 Adapt مشاريع (قائمة حقيقية + تفصيل)
- **النطاق:** GET /api/projects → ListQuery (إزالة pageSize=1000)؛ تفصيل مشروع (إعادة استخدام الموجود أو بناؤه بعد WP-0.1)؛ دعم حقول contractValue/region/notes الحية.
- **التبعيات:** WP-0.1 (تفصيل موجود؟)؛ لا يعتمد على schema.
- **اختبار:** ترقيم صفحات؛ فلاتر النطاق في الاستعلام (لا فلترة لاحقة)؛ 404/403 صحيحة.
- **معيار القبول:** الواجهة تعرض الحقيقي بلا hack؛ سلوك identical للـ POST/PUT القائمة.

## 2. P1 — الإصدار الأول القابل للاستخدام (الموديولات الستة)

### WP-1.1 Projects — دورة الحياة الكاملة
- **النطاق:** حذف منطقي + استرجاع (O12)؛ بوابة رؤية المحذوف (D2)؛ contractValue (NULL≠0)؛ منع إعادة فتح completed/cancelled (D5 يوازي)؛ تدقيق كل كتابة.
- **التبعيات:** WP-0.2، WP-0.4. **schema:** أعمدة الحذف. **API:** DELETE/restore/list-deleted [Proposed-READY].
- **واجهة:** شاشة Projects الحالية + شريط "المحذوف" لأصحاب البوابة.
- **تخويل:** projects.delete + projectAccess=DELETE.
- **اختبار:** soft-delete يخفي من القوائم والبحث والعدادات؛ بوابة المحذوف = 403 لغير المصرح؛ 409 PROJECT_DELETED على كتابة محذوف.
- **معيار القبول:** لا سجل يختفي نهائيًا؛ لا تسريب عدادات (INV-D2).
- **قرار حاجب:** D2 (بوابة المحذوف) — يمكن الإطلاق ببوابة افتراضية المشروحة ثم التعديل.

### WP-1.2 Archive — المستندات والمجلدات والانتقالات
- **النطاق:** قوائم/تفصيل/رفع/مراجعة/تنزيل/حذف منطقي/روابط؛ مصفوفة O3 (المرجع الوحيد 01 §4.3)؛ ربط-مشروع بنطاق ≥ READ.
- **التبعيات:** WP-0.1 (موجود endpoints؟ filePath، allowlist)؛ WP-0.2. **لا استيراد CSV هنا** (P2 بعد تثبيت العقد).
- **API:** موثق 03 §5 (خليط UNKNOWN/PROPOSED) — البناء يبدأ من الجرد.
- **تخويل:** archive.* + WRITE/DELETE للمشروع.
- **اختبار:** مصفوفة الانتقالات (كل مسار مسموح + كل مسار مرفوض 409)؛ منع رافع آخر مراجعة من اعتمادها إن اعتمد D3.
- **معيار القبول:** لا انتقال خارج المصفوفة؛ لا تنزيل لغير ≥ READ؛ unavailable envelope صحيح.
- **قرارات حاجبة:** D3 (فصل مهام) اختياري؛ D6 (حدود الملفات) — افتراض محافظ إن لم يُحسم.

### WP-1.3 Finance/IPC — BOQ + دورة IPC الرسمية
- **النطاق:** عرض/تحرير BOQ؛ IPC بجميع الانتقالات عبر `ipc_status_events`؛ اعتماد/رفض بـ `ipcs.approve`؛ إعادة تقديم؛ منع الاعتماد الذاتي؛ unavailable (O5/O6) في كل بطاقات المال.
- **التبعيات:** WP-0.2، WP-0.3، D1 (اختياري للإطلاق).
- **API:** 03 §6.3 [Proposed-READY].
- **اختبار:** مسار كامل draft→submitted→approved وrejected→draft→submitted؛ SELF_APPROVAL_DENIED موثق؛ بديل مؤقت projects.edit **يُمنع** بمجرد تفعيل المفاتيح.
- **معيار القبول:** لا انتقال بلا حدث مسجل (INT)؛ لا قيمة مالية مُصطنعة (C6).
- **قرار حاجب:** D1 (يُفضَّل قبل واجهة أزرار الاعتماد).

### WP-1.4 Administration — المستخدمون والصلاحيات
- **النطاق:** CRUD مستخدمين (+dept/title)؛ تجاوزات INHERIT/GRANT/DENY؛ إدارة وصول المشاريع (مشروطة D7)؛ تعطيل/تفعيل (LAST_ADMIN)؛ إعادة تعيين إدارية (اختياري — قناة تسليم D-تشغيلي).
- **التبعيات:** WP-0.2، WP-0.3. **schema:** أعمدا المستخدمين.
- **اختبار:** DENY يقطع فورًا؛ fallback viewer لدور غير معروف؛ تعطيل آخر admin → 409؛ تجاوز GRANT لمفتاح B1 يجعل المستخدم قادرًا.
- **معيار القبول:** لا إسناد دور مُخترع؛ prototype-only keys لا تظهر إلا بعد تأسيسها.
- **قرارات حاجبة:** D7 (مفاتيح الإدارة الإضافية).

### WP-1.5 Dashboard — العدادات التشغيلية
- **النطاق:** عدادات (مشاريع/مستندات/IPC/تنبيهات) بموجود المستخدم؛ عدّاد المحذوف لأصحاب البوابة؛ **بلا قسم مالي** (O7).
- **التبعيات:** WP-1.1/1.2/1.3 (مصادر العدّادات).
- **اختبار:** نفس المستخدم يرى عدادات متوافقة مع قوائمه؛ لا عدّ لمصادر غير مصرح؛ مستخدم بصلاحية صفرية يرى لوحة شاغرة بلا أخطاء.
- **معيار القبول:** صفر تسريب (INV-D2) — رقم يظهر فقط لمصدر يراه المستخدم.

### WP-1.6 Audit — السجل والفلاتر
- **النطاق:** قائمة + فلاتر (مستخدم/نوع/فترة/مشروع-إن O8)؛ مقلم oldValue/newValue/ipAddress لغير admin؛ diff كامل للـ admin.
- **التبعيات:** WP-0.2 (عمود projectId اختياري)؛ كتابة التدقيق في WP-1.1–1.4.
- **اختبار:** فلترة بمشروع تتطلب ≥ READ؛ append-only (لا تحديث/حذف عبر API)؛ الإخفاء الحساس (passwordHash/رموز).
- **معيار القبول:** كل كتابة P1 لها حدث تدقيق ضمن نفس المعاملة.

### WP-1.7 Global Search — بحث خلفي
- **النطاق:** مشاريع+مستندات (نطاق لكل عنصر)؛ استعلامات مُسندة بلا تسرّب (06 §5).
- **التبعيات:** WP-1.1، WP-1.2؛ O9 [Confirmed].
- **اختبار:** عنصر غير مصرح لا يظهر كعنوان/مقتطف/عدد؛ استجابة موحدة القياس.
- **معيار القبول:** لا معلومة مستنتَجة عن وجود بيانات غير مصرح.

**معيار قبول الإصدار الأول (خليط):** كل شاشة تعرض حالاتها الخمس الصحيحة (loading/empty/error/forbidden/unavailable)؛ fixture معطل في الإنتاج ومعلَّم؛ لا وهم تكامل (04 §13).

## 4. Deferred (صريحًا)
- **O5/O6** الصرف/الضريبة/الاستقطاع/المقدمات — حتى مصادر بيانات حقيقية (عرض unavailable دائمًا).
- **Backup/restore تشغيليًا** — تصميم جاهز؛ التنفيذ عملية تشغيلية (P3) بمصادقة مالك وبيئة معزولة للاختبار الدوري.
- **أدوار مخصصة (roles.manage)** و**دخول بالإيميل** — قرارات مالك مستقلة.
- **تقطيع hash-chaining للتدقيق** — تحسين لاحق.
