## 2. انعكاس B1 — القرار المعتمد حرفيًا

| البند | الحالة |
|---|---|
| `ipcs.approve` + `ipcs.resubmit` إضافتان معتمدتان لمفردة الصلاحيات (`ALL_PERMISSIONS`) | **APPROVED (B1)** — قرار مالك نهائي |
| تعديل `ROLE_BASE` الحالي تلقائيًا | **ممنوع** — لا تغيير |
| إسناد المفتاحين لأدوار معينة | **لم يُعتمد بعد** — مصفوفة 14B-05 §6 (admin+management للـ approve؛ admin+technical للـ resubmit) تبقى **[Proposed — قرار D1]** |
| طبقات الاحتساب الثلاث + DENY precedence + projectAccess | **محفوظة كما هي** — B1 لا يمسها |
| قيد منع الاعتماد الذاتي | **محفوظ** — مستقل عن الأدوار: 403 `SELF_APPROVAL_DENIED` |

**النتيجة المنطقية للنموذج (بلا إسنادات جديدة):** بعد إضافة المفتاحين للمفردة، لا دور يملكهما ضمن ROLE_BASE → لا أحد يوافق/يعيد تقديم إلا بتجاوز مستخدم صريح (GRANT) — وهو سلوك سليم آليًا حتى اعتماد مصفوفة الأدوار (D1).

## 4. متطلبات فرض التخويل (Enforcement) — التصميم [Proposed-READY تطبيقاً]

1. **كل نقطة تتحقق ذاتيًا:** مصادقة → صلاحية عامة → نطاق مشروع → ملكية/حالة. لا ثقة بأي مرجع من العميل.
2. **حساب مركزي واحد** (مُحلّل واحد) لا يتكرر لكل نقطة — يمنع التفاوت.
3. **نطاق القوائم في الاستعلام نفسه** (JOIN/WHERE على projectAccess) — لا فلترة بعد الجلب (O9/O7).
4. **IDOR:** التفصيلي يمر بنفس البوابة — لا استثناءات.
5. **فشل التخويل على كتابة حرجة** يُسجل تدقيقيًا (actor, action, resource).
6. **منع الاعتماد الذاتي (O4):** actor == مُقدِّم الحالة الأخيرة → 403 SELF_APPROVAL_DENIED — خلفي، بغض النظر عن الصلاحية.

## 7. التغييرات المطلوبة عند التفويض (لا تُنفذ الآن)

1. إضافة `ipcs.approve` + `ipcs.resubmit` إلى `ALL_PERMISSIONS` (وبناء عليه يصبحان في صلاحيات admin تلقائيًا عبر `admin: [...ALL_PERMISSIONS]` — **أثر جانبي يجب إعلانه للمالك**: admin يملكهما فورًا بالبنية الحالية. هذا ليس "تعديل ROLE_BASE" بل اتباعها؛ يُعلَّم بوضوح في التنفيذ).
   - **ملاحظة اتساق:** منع الاعتماد الذاتي يغطي حالة admin=مُقدِّم؛ ولا يخلق تناقضًا مع O13.
2. **حسم D1** (إسناد الأدوار) قبل أي واجهة أزرار IPC: إما اعتماد مصفوفة 14B-05 §6 أو تركها GRANT-تجاوزات يدوية.
3. توسيع مجموعة «الإدارة» في الواجهة بالمفتاحين عند توفرهما (عرض مشروط بمتناول الفعلي).
4. فرض القاعدة الشخصية SELF_APPROVAL_DENIED في مسار انتقالات IPC.
5. تحديث mock (`MANAGED_GROUPS`) ليطابق المفردة النهائية **فقط بعد** تنفيذها خلفيًا — لا قبلها.
6. جرد مصرَّ به يتحقق: هل توجد آلية تخويل خلفية تدعم مفردة ديناميكية أم قائمة ثابتة؟ (أثر تنفيذي محجوب داخل المحميات).
