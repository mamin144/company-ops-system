# Phase 14C — الوثيقة 03: جاهزية المخطط والبيانات (Schema & Data Readiness)

> **المقارنة:** نموذج البيانات الهدف (14B-02) مقابل **كل دليل مخطط متاح بأمان** — دون اتصال DB، دون SQL، دون migrations أو seeds.
> **مفتاح التصنيف (7 درجات):** (1) موجود ومُدقق · (2) موجود وقيوده مجهولة · (3) عمود إضافي جديد · (4) جدول إضافي جديد · (5) يحتاج معالجة توافق · (6) يحتاج قرار مالك · (7) محجوب بمصدر محمي.

## 4. الأساسي للإصدار الأول مقابل المؤجل

### أساسي (Essential — P0/P1)
1. `users.department` + `users.title` (3) — **المهمة الوحيدة في migration** (14B-07 R-5 F3): عمودان nullable additive.
2. `projects.deleted_at/deleted_by` (3) — شرط O12 (الحذف المنطقي + بوابة الرؤية).
3. `ipc_status_events` (4) + قيمة `under-review` (5) — شرط دورة IPC بعد مفاتيح B1.
4. `audit_logs.projectId` (3) — يمكن الإطلاق بدونه (O8 اختياري) لكنه رخيص ويفتح فلتر التدقيق بالمشروع — يُدرج ضمن P1 إن استُكمل D-واجهة فلترة.

### مؤجل (Deferrable)
- `password_reset_tokens` — بعد قرار قناة التسليم (D-تشغيلي) وعند P2.
- `backups`/`restore_jobs` — عند بدء العملية التشغيلية (P2/P3).
- `import_batches` — بعد إزالة عائق كشف التكرار الخلفي.

### محجوب (Blocked)
- تأكيد القيود الفعلية لكل ما سبق: **قيد إلزامية/تفرّد/فهارس `users.email` القائم، تفرّد projectCode/username/ipcNumber، وجود أعمدة الحذف المنطقي مسبقًا** — كلها (7) تُحسم من مخطط DB الفعلي/ملفات migrations بمصادقة مالك.

## 5. معالجة التوافق (Compatibility) — استراتيجية additive-only

1. **كل التغييرات إضافية:** أعمدة nullable، جداول جديدة، قيم enum جديدة — لا rename ولا drop ولا تعديل معنى.
2. **نقطة ترحيل وحيدة معلنة:** إدخال `under-review` → تحديث كل تحليل حالة (switch/عرض) — يُنفذ مع migration IPC في P1.
3. **لا يُنفذ أي migration قبل:** مراجعة مصدر مصرَّ بها للمخطط الفعلي (الملفات المحمية + ملفات `apps/api/src/database/migrations/`) — شرط بوابة P0-Schema.
4. **حد فشل المعاملات (INT-3):** تدقيق كل كتابة ضمن نفس معاملة العملية.
5. **لا استبدال صامت:** استيراد/استرجاع/حذف تُعلن ما فعلته بالضبط.

## 6. ما الذي **لا** يُفعل في هذه المرحلة (صريحًا)

- لا اتصال بقاعدة إنتاج ولا قراءة مخطط منها.
- لا كتابة migration/seed SQL في هذه الوثيقة (التصميم أسماءً ومبادئ فقط).
- لا قيود مُخترعة على `users.email` — ولو بدا صحيحًا أن التفرّد "واضح".
- لا إعادة تسمية أو دمج حقول قائمة.
