## 1. الحالة: PASS WITH LIMITATIONS

إنجاز المرحلة **كما عرّفتها الخطة**: جميع المخرجات الثمانية §305–313 مُنتجة ومُوثقة بأدلة جديدة طازجة (fresh) من هذا اليوم، بما فيها إعادة البناء الإنتاجي على مجلد جديد وإعادة تشغيل المجموعة الاختبارية الكاملة **322/322** ضد نُسخة التسليم نفسها.

القيود ( Limitations ) التي تمنع `PASS` المطلق وتَرُدّ الإعلان عن جاهزية الإنتاج:

1. **محول HTTP الحقيقي غير مُتبنى** — طبقة `src/services/api/configuration.ts` وُثِّقت فيها صراحةً أن النقل الوحيد الزمن تشغيل هو محول المحاكاة المعزول، وطبقة HTTP (`client.ts`/`errors.ts`) هيكل عظمي غير مسجَّل كمحول، لأن خريطة عقود API (مخرج Phase 1) لم تُنتَج. بناء المحاكاة الناجح لا يثبت وحده جاهزية الإنتاج.
2. بناء الإنتاج حاليًا **يتطلب** `VITE_PROTOTYPE=1`؛ بدونها يَرمي محول المحاكاة خطأً وقت الاستيراد (حارس مقصود).
3. لا قرار نشر أو بيئة نشر للواجهة مُختارة؛ إجراءات التحويل موجودة **كوثيقة فقط**.

## 2. النطاق: ما نُفّذ وما لم يُنفّذ

**نُفّذ:**
- إعادة تفحص الحالة القبل التنفيذ (فرع، HEAD، `git status --short`، فروق) دون أي إعادة ضبط أو استبدال تغييرات قائمة.
- التحقق من إصلاحات Phase 10.1 الحالية (اختبارات admin/archive/i18n/phase7-archive) ووجود ملفَّي fixtures الدائمين `verify/fixtures/replacement.txt` و `import-mixed.csv` (True / True).
- Typecheck مدخل جديد، بناء إنتاجي جديد على مجلد تسليم جديد `dist-phase11/` (لم يُمس `dist-phase10/` أو أي مخرجات سابقة)، وخادم معاينة جديد على المنفذ **5206** (كان حرًّا؛ :5205 لم يُعتبر حاضرًا دون فحص — ووُجد حيًّا HTTP 200 لكن تحقق التسليم نُفّذ على البديل النظيف).
- إعادة تشغيل **المجموعة الكاملة** (27 ملف verify، 322 اختبارًا) ضد `dist-phase11/` عبر `PLAYWRIGHT_TEST_BASE_URL=http://localhost:5206` — نتيجة طازجة: 322 passed، 0 failed، لا skip/fixme.
- الجرد النهائي: 55 ملف src، 27 ملف verify، اللغات، إعدادات build/PWA، الاعتماديات، 190 ملف غير متتبع تحت `docs/`.
- مُخرج إجراءات الاستبدال/الرجوع **كوثيقة فقط**: `docs/frontend-rebuild/phase-11/phase-11-swap-rollback-procedure.md`.

**لم يُنفّذ (خارج النطاق وفق الخطة/التفويض):**
- لا بناء محول HTTP حقيقي ولا خريطة عقود API (يتطلب تفويضًا منفصلًا).
- لا deployment، لا DNS، لا push، لا merge، لا commit، لا migration، لا تغيير إعدادات خدمة.
- لا بدء أي مرحلة لاحقة.

## 3. المعمارية والصفحات والمكونات واللغات والتبعيات

### المعمارية

- **التقنيات المعتمدة محفوظة:** React + TypeScript + Vite (خانة §9(3) من القبول النهائي).
- نموذج فعلي معزول بذاته في `docs/frontend-rebuild/phase-03-prototype/` مع جملة تكوين خاصة (`vite.config.ts`: base `/`، server/preview :5199، outDir `dist`) ولا يستورده أي `apps/*`.
- بنية المقاطع (55 ملفًا تحت `src/`): `app/`، `components/`، `features/` (7 وحدات: administration، archive، dashboard، inventory، projects، reports، requests)، `i18n/`، `mock/`، `services/` (طبقة المحولات + إعداداتها)، `shared/` (أنماط وقيم مشتركة).
- بنية البيانات بواجهة موحّدة `ApiAdapter`: الوحيد المسجَّل زمن تشغيل هو المحول البديل المعزول؛ مدخل الاختيار `IS_PROTOTYPE`/`API_MODE` في `src/services/api/configuration.ts`.
- اختبارات تسليم مستقلة تحت `verify/` (27 ملفًا، 322 اختبارًا، Playwright) مع fixtures دائمة.

### الصفحات (الوحدات)

سبع وحدات كاملة: لوحة القيادة، المشروعات، المخزون والمواد، طلبات المواد، التقارير، الأرشيف، الإدارة (المستخدمون/الأدوار/الإعدادات) — كلها مُغطاة في مصفوفة التكافؤ النهائية (بند 7 أدناه).

### المكونات

مكونات shell مشتركة (تنقّل، لوحات، جداول، نماذج بـ anatomy موحّد `.field` و`role="alert"`، حالات loading/empty/error/disabled/permission-denied)، عناصر dialog/drawer بدعم Escape والتركيز، مشغّلون per-feature (mock adapters) لكل وحدة.

### اللغات

- `ar` افتراضيًا مع `dir="rtl"`، `en` مع `dir="ltr"`; حفظ الاختيار في `localStorage` بمفتاح `cos-proto-lang`.
- استعادة اللغة قبل الرسم في `index.html` (سكربت pre-paint) مع مُرآة مطابقة في `src/i18n/direction.ts`؛ الشِعار كاملان `src/i18n/ar.ts` و `en.ts` (لا سلاسل مرئية غير مترجمة — مُثبت بحقيبة i18n 28/28 الطازجة).
- RTL/LTR عبر CSS logical properties؛ عناصر LTR المنطقي (emails، IDs، مسارات، serials) محفوظة.

### التبعيات

- **عقيدة التسليم:** التبعيات المستخدمة داخل النموذج هي تلك المثبتة في `docs/frontend-rebuild/phase-03-prototype/package.json` (React/TS/Vite/Playwright وتبعيات دعم النموذج). لم تُضَف أي تبعية جديدة في هذه المرحلة (Phase 11) — لا تثبيتات نُفِّذت ضمن التفويض.
- ملاحظة فروق سابقة (ليست من هذه المرحلة): تعديل `package.json` في جذر المستودع يضيف devDep الشيفرة `shadcn` وتبعيتي `gsap`/`@gsap/react`/`lenis` — موجود قبل بدء Phase 11 وليس مخرجها (انظر §8).

## 4. التغييرات في إعدادات Frontend / Build / PWA وأثرها

- **لا حاجة لتغيير أي إعداد برمجي في هذه المرحلة.** الإعدادات الفعلية كما هي:
  - `vite.config.ts`: `base '/'`، `server.port 5199`، `preview.port 5199`، `build.outDir 'dist'`، `emptyOutDir true`.
  - أمر التسليم استخدم **مجلدًا جانبيًا عبر CLI** (`--outDir dist-phase11 --emptyOutDir`) بدل تغيير التكوين — حفاظًا على مخرجات المراحل السابقة (`dist-phase10/` بقي سليمًا: assets + logos + index.html، تم التحقق).
- **PWA:** لا يوجد `manifest.webmanifest` كاملاً؛ لم يُضاف في المرحلة 11 لأن الخطة لم تفرضه عليها ولا على المراحل السابقة كشرط تسليم. الحالي: `theme-color` فقط + سكربت استعادة اللغة قبل الرسم. إذا طلب المالك جاهزية PWA للنشر، فهذا بند لاحق يحتاج قرارًا (أثره: النسخة الحالية لن تُقدَّم كتطبيقًا قابلًا للتنصيب كما هو).
- **أثر تبديل المنفذ:** خادم التسليم شُغِّل على :5206 (`--strictPort`، المنفذ كان حرًّا)؛ متغير `VITE_PROTOTYPE=1` مطلوب أثناء البناء والمعاينة. خادم :5205 التاريخي وُجد حيًّا (HTTP 200) ولم يُعطَّل أو يُقاطَع.

## 5. قائمة المتطلبات البيئية وخطوات التشغيل المحلية + تحقق نسخة الإنتاج

### المتطلبات

- Node.js (الإصدار المثبّت: Node/npm الحالي للجهاز، lockfile المستودع).
- الحزم: `npm install` في جذر المستودع (التبعيات مشتركة عبر جذر المستودع؛ النموذج لا يعمل بمعزل عن `node_modules` الجذر).
- متغير البيئة الإلزامي للنموذج: `VITE_PROTOTYPE=1`.

### التشغيل المحلي (تطوير)

```
cd docs/frontend-rebuild/phase-03-prototype
$env:VITE_PROTOTYPE='1'
npm run dev            # أو: npx vite  (منفذ 5199 افتراضيًا)
```

### البناء والمعاينة (كما نُفّذ في هذه المرحلة حرفيًا)

```
npx tsc --noEmit
$env:VITE_PROTOTYPE='1'; npx vite build --outDir dist-phase11 --emptyOutDir
$env:VITE_PROTOTYPE='1'; npx vite preview --outDir dist-phase11 --port 5206 --strictPort
```

- ملاحظة: في vite 7، أمر preview يأخذ `--outDir` (التمرير الموضعي رُفض في محاولة أولى — `Error: The directory "dist" does not exist`-مثلًا؛ المستند يثبت الملاحظة).
- **تحقق نسخة الإنتاج المبنية:** `dist-phase11/` (7 ملفات: index.html + assets/index-PmYGrnNN.css 31.71 kB + assets/index-CMgkjhs9.js 699.33 kB gzip 214.95 kB) خُدِمت عبر HTTP 200 (index + JS asset)، وأعيد تشغيل المجموعة الاختبارية الكاملة ضد العنوان الحي — النتيجة §6. **نسخة الإنتاج المبنية والمفحوصة هي نفسها نُسخة التسليم المُشار إليها في هذا التقرير** (نفس مجلد البناء، دون أي إعادة إخراج وسطية).

## 13. بوابة التوقف

لم يُنفَّذ: **لا commit، لا push، لا merge، لا إنشاء فرع جديد، لا نشر أو DNS، لا تشغيل migrations، ولا بدء أي مرحلة لاحقة.** كل ما نُفّذ محصور في التحققات ووثائق Phase 11 في شجرة العمل الحالية. أي خطوة لاحقة (استبدال فعلي، بناء المحول الحقيقي، نشر، دمج الفرع الأساسي) تتطلب موافقة صريحة منفصلة من المالك.
