# إجراء استبدال نسخة الواجهة والرجوع عنها — وثيقة فقط (Phase 11)

**النطاق:** هذا المستند **إجراءات مكتوبة فقط**، وفق الخطة §305–315: «إجراءات استبدال نسخة الواجهة والرجوع عنها كوثيقة فقط؛ لا تنفذ deployment أو DNS أو push». لم يُنفَّذ أي أمر من هذا الملف فعليًا، وكل الخطوات تتطلب موافقة صريحة منفصلة من المالك.

---

## 1) السياق الحقيقي قبل الاستبدال (قراءة إلزامية)

- مخرج التسليم النهائي هو **نموذج تفاعلي كامل** في `docs/frontend-rebuild/phase-03-prototype/`، تعمل بياناته عبر محول المحاكاة المعزول (`src/services/api/adapters/mock/`).
- `VITE_PROTOTYPE=1` يختار محول المحاكاة (`IS_PROTOTYPE` في `src/services/api/configuration.ts`). **بدون هذه العلامة يرمي محول المحاكاة خطأً وقت الاستيراد ولا يرتد بهدوء إلى نسخة أخرى** — هذا الحارس مقصود لمنع تسرب أدوات المحاكاة إلى أي بناء آخر.
- **النقل الحقيقي لم يُبنَ بعد:** طبقة HTTP (`client.ts`/`errors.ts`) هيكل عظمي غير مسجَّل كمحول زمن تشغيل، لأن خريطة عقود API (مخرج Phase 1) لم تُنتَج. هذا هو **الشرط الأول** لأي استبدال فعلي ويحتاج تفويضًا مستقلًا.
- لذلك: الإجراء أدناه يغطي **استبدال التجربة المرئية/التفاعلية** المتاح اليوم (وضع المحاكاة فقط)، ويحدد خطوة الربط الإنتاجي بوصفها مُخرجًا منفصلًا.

## 2) خطوط أنابيب ما يُستبدل

| العنصر | المسار الحالي (v1) | المخرج الجديد |
|---|---|---|
| الواجهة الحية | `apps/web/**` (React/TS/Vite، بناؤها عبر `npm run build --workspace @cos/web`) | `docs/frontend-rebuild/phase-03-prototype/**` |
| البناء | بناء الـ workspace | `npx vite build --outDir <dir> --emptyOutDir` مع `VITE_PROTOTYPE=1` حتى إتمام الربط الإنتاجي |
| Backend/DB/RBAC | `apps/api/**`, `packages/**`, PostgreSQL | **لا يُلمَس إطلاقًا** — قرار Option A حاكم |

## 3) إجراء الاستبدال (وثيقة فقط)

1. **بوابة 1 — موافقة المالك:** موافقة صريحة مكتوبة على تقرير Phase 11 ومصفوفة التكافؤ النهائية.
2. **بوابة 2 — الربط الإنتاجي (تفويض مستقل):** انتاج خريطة عقود API، ثم بناء محول HTTP حقيقي يحقّق واجهة `ApiAdapter` نفسها وتسجيله في `configuration.ts` بدل mock، ثم إعادة تشغيل المجموعة الكاملة **بدون** `VITE_PROTOTYPE=1` على بيئة تجريبية ضد `apps/api`.
3. **بيئة التشغيل:** استضافة static لواجهة الفرع المعتمدة مع reverse proxy للمسار `/api` نحو `apps/api` (قيمة `API_BASE_URL` الافتراضية `/api`). لا قرار DNS في هذه الوثيقة.
4. **بناء النسخة القابلة للاستبدال:** نفس أمر البناء المشهود (نمط دفعة `dist-phase11`)، وتشغيل سوِيت Playwright الكامل على عنوان البيئة الجديدة مع نتيجة **322/322** مسجلة قبل أي تبديل.
5. **الإبعاد التدريجي:** نشر الواجهة الجديدة تحت مسار مرآة (مثال: `/v2`) مع بقاء v1 على `/` حتى القبول النهائي. لا توجد أداة نشر مختارة للواجهة اليوم؛ أدوات التشغيل الحالية (`scripts/install-service.ps1`) تخص خدمة Windows للـ API فقط.
6. **فترة الفحص用具:** مقارنة حية مع مستخدمين حقيقيين منقولين (دور لكل فئة A1–H1 في المصفوفة)، بمدة تجريبية متفق عليها كتابةً.
7. **التبديل النهائي:** تحويل `/` إلى النسخة الجديدة فقط بعد موافقة مكتوبة على نتائج الفترة التجريبية.
8. **التسجيل:** توثيق تتابع النشر بوقته وهويته ومسؤول تجريبه في مستند المالك (خارج هذه الوثيقة).

## 4) إجراء الرجوع (وثيقة فقط)

1. **مبدأ النسخة المحمية:** v1 محفوظة **بلا تعديل** في مسارها الأصلي `apps/web/**` (قرار الخطة §42/§4 حاكم). الرجوع يعني **إعادة توجيه المسار `/` إلى نفس بناء v1 المحفوظ** — لا إعادة بناء ولا إصلاح تحت الطوارئ.
2. **قبل أي تبديل:** تُؤخذ نسخة محفوظة من بناء v1 الحالي (أرشيف خارج المستودع) مع تسجيل SHA للـ commit المصدر (`f91ed2f9e81db3937e3bcbb1b44e5e2c44e175cf`) في سجل التسليم.
3. **خطوات الرجوع:** (أ) إعادة توجيه `/` إلى بناء v1 المحفوظ، (ب) سحب الإتاحة الخارجية عن v2، (ج) حفظ نسخة fallback من v2 في مجلد مؤرَّخ، (د) صفر تعديل في backend/DNS عبر كل الخطوات.
4. **اختبار سلامة الرجوع (قبل أي تبديل فعلي):** تشغيل v1 على منفذ تحقق محلي (بنمط :5204 المستخدم خط الأساس في المرحلة 10)، ومراجعة سريعة لصفوف بعينها من المصفوفة (A1–A4 وH1)، ثم حسم جاهزية البديل.
5. **المسار العملي الوحيد للرجوع:** تغيير إعدادات التوجيه فقط (reverse proxy)، بلا migration أو seed أو تغيير حاوية، ضمن نافذة متفق عليها مسبقًا.

## 5) بنود مفتوحة قبل أي تطبيق لهذا الملف

| # | بند | الحالة |
|---|---|---|
| 1 | الربط الإنتاجي مع `apps/api` (محول HTTP حقيقي) | غير منجَز — يتطلب تفويضًا مستقلًا؛ خريطة العقود لم تُنتَج في Phase 1 |
| 2 | موافقة النموذج التفاعلي بعد التجربة | تنتظر قرار المالك |
| 3 | الفترة التجريبية بمستخدمين حقيقيين (5 أدوار) | بحاجة تنسيقات بيئة خارج هذا التفويض |
| 4 | أداة/بيئة نشر للواجهة | غير مقررة — قرار المالك |

---

## 6) بوابة التوقف

لم تُنفَّذ أي خطوة من هذا الملف فعليًا: لا نشر، ولا DNS، ولا push، ولا تغيير أي إعداد توجيه أو خدمة، ولا دمج. هذا المستند هو تسليم الخطة §312 بعينه (كوثيقة)، ولا يبدأ تنفيذ أي بند فيه إلا بموافقة المالك الصريحة المنفصلة.
